# 語彙DBのキャッシュ

## 扱うこと

語彙DBを処理の中で引くとき、どう読むか

## 答え方と理由

### 0. 判断全体

なし

### 1. 語彙DBを引く関数は、セッション内でキャッシュする

語彙DBを引く関数は、必ずセッション内でキャッシュする。 モジュール変数に1つ持ち、`force_reload=True` のときだけ引き直す。

```python
_cache = None

def load(force_reload=False):
    global _cache
    if not force_reload and _cache is not None:
        return _cache
    _cache = _fetch()      # ← Notionを引くのはここだけ
    return _cache
```

1. （原因）Notionのクエリは1回2〜3秒かかる。「1レコードごとに引く」形を書くと、件数ぶんのAPI往復になって実用にならない。このスキルを使う側で3回踏んでいる。3回目は、語彙DBを1行ごとに引いて107行でタイムアウトした。遅さは「待たされる」だけでなく失敗として現れる。（発生日：2026-09-12）

   | どこ | 症状 |
   |---|---|
   | ルール表の読み込み | 処理の種類ごとに、同じ数百行のルール表を引き直していた |
   | 表示名の辞書 | 取り込みが1レコードごとに辞書を引いていた |
   | 語彙の検査 | 1行ごとに語彙DBを引き、百行ほどでタイムアウト（exit 143） |

### 2. 書き込みの直後は `force_reload=True`

書き込みの直後は `force_reload=True`。 足した行を読み直さないと、同じセッションの次の判定が古い語彙で動く。

1. 記録なし

### 3. キャッシュはセッション内だけ

キャッシュはセッション内だけ。 ファイルに落とさない。

1. （根拠）ファイルに落とすと、Notion側で人が直した値と食い違い、どちらが正か分からなくなる。（決定日：記録なし）

### 4. `import` 時には引かない

import時には引かない。

1. （根拠）モジュールを読むだけで通信と認証が要る作りにすると、ネットワークの無い場面（テスト・構文確認）で読み込みそのものが落ちる。（決定日：記録なし）

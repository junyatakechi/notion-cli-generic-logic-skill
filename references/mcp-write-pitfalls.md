# MCPで本文を書くときの崩れ

## 扱うこと

公式MCPで本文を書く・書き替えるとき、表のセル・強調・置き換え・差し込む位置で崩れないよう、どう書くか

## 答え方と理由

### 0. 判断全体

頼んでいないリンクの防ぎ方は、この判断では答えない（→ [MCPで本文を書くときのリンク化](mcp-autolink.md)）。コメントの付いた表を増減させるときの扱いは、この判断では答えない（→ [コメントの扱い](comments.md)）。

### 1. 表のセルにHTMLタグを書かず、セルの中も Markdown の記法で書く

表のセルに `<b>`・`<code>` などのHTMLタグを書かない。セルの中も、`**太字**`・`` `コード` `` の Markdown の記法で書く。`<table><tr><td>` の形で書いても、パイプの形で書いても、セルの中の書き方は同じにする。同じページの中で書き方を混ぜない。

1. （原因）表のセルに書いた `<b>` や `<code>` が文字としてエスケープされ、`\<b\>` と表示された。同じページで書き方を混ぜると、片方だけが壊れて気づきにくかった。（発生日：2026-08-30）

### 2. `**太字**` の直後にコード表記を続けない

`**太字**` の直後に、コード表記を続けない。太字とコードを並べたいときは、間に空白か語を挟むか、どちらか一方に寄せる。

1. （原因）`**（****`/c/Users/...`****）**` のように、太字の区切りが崩れた。（発生日：2026-08-30）

### 3. `update_content` の `old_str` は、`notion-fetch` の出力からそのまま写し、置き換えたら警告を見る

`update_content` の `old_str` は、記憶で書かず、`notion-fetch` の出力からそのまま写す。表の `<td>` や、コードブロックの中の空白も含める。置き換えたら、応答に警告が返っていないかを見る。

1. （原因）記憶で書いた `old_str` が本文と一致せず、置き換わらなかった。一致しなかった置き換えは、警告に出るだけで、エラーにならなかった。（発生日：記録なし）

### 4. 見出しの直後に区切り線があれば、見出しと区切り線の2行を `old_str` にして、その下に差し込む

見出しの直下に差し込むとき、見出しの直後に区切り線 `---` があれば、`old_str` に見出しと区切り線の2行を含め、`new_str` で区切り線の下に足す。見出しだけを `old_str` にしない。区切り線が無ければ、見出しの1行だけにする。見出しの行は部分一致で探さず、本文に出てくる行をそのまま写す。見出しが無いときは、`insert_content` でページの末尾に、見出しごと足す。

1. （原因）見出しだけを `old_str` にすると、差し込んだものが区切り線の上に入った。（発生日：記録なし）

### 5. 差し込むときは最小の差分にし、既存のブロックを再送しない

差し込むときの置き換えは、見出しと区切り線だけを対象にした最小の差分にする。その下にある既存のブロックを `old_str`・`new_str` に含めて送り直さない。既存のブロックの並び替えや、見出しのレベルの一括変更のような、範囲ごとの置き換えは、頼まれたときだけ行う。

1. （根拠）トークンの消費と、Notion側の処理の負荷を抑える。最小の差分なら、既存のブロックはそのまま残る。（決定日：記録なし）

### 6. `replace_content` で全体を書き替えると、本文に付いたコメントが位置を失う

`replace_content` で本文の全体を書き替えると、本文に付いたコメントは付いていた位置を失う。構成を丸ごと変えるとき以外は、`update_content` で部分を書き替える。

1. （原因）`replace_content` で全体を書き替えると、コメントがアンカーされていた位置を失った。（発生日：記録なし）

### 7. 書いたら、プロパティだけでなく本文も読み直す

公式MCPで書いたら、`notion-fetch` で本文も読み直し、`\<` のようにエスケープされたタグと、崩れた太字が無いかを見る。プロパティだけを見て終えない。

1. （原因）答え方1・2の崩れは、作成後にプロパティだけを確かめて終えると、気づけなかった。（発生日：2026-08-30）
